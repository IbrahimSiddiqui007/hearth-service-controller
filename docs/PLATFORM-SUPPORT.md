# Platform support and verification

Updated October 16, 2026. Source adapters for Linux/macOS/Windows suspend and shutdown are implemented with fixed commands, independent signing, separate controller/agent approval and ordinary-account checks. Grouped schedules and IANA/DST schedules are implemented. Native permissions and behavior remain unverified; no power command or privilege grant was performed on a real target.

Hosted CI passed on Windows, Linux and macOS: **382 backend tests passed on each runner**, plus the frontend build and nine Node tests. These are fixture/mocked-provider checks, not evidence of target enrollment, service control, native file replacement or measured hardware budgets. See [verification evidence](VERIFICATION.md), [scope contracts](POWER-AND-SCHEDULES.md) and [first deployment acceptance](FIRST-DEPLOYMENT.md).

The ledger's status labels are **Done**, **Partial** and **Not started**. Six rows remain **Partial** because native/platform verification is incomplete; collecting that evidence is deferred at the owner's request. Deferral is a separate verification decision, not another implementation status.

Linux scans do not include Flatpak, Snap, AppImage, every custom install prefix or other users' applications. macOS scans do not include Homebrew, installer receipts, background-item databases or other users' apps. Application metadata is not proof of its owning service or a safe removal operation. Package and bundle commands/URLs never become executable controls.

macOS `launchctl list` observes the agent's current launchd context, not every user's GUI context or the full system daemon domain. Apple jobs are hidden in normal scans; an explicit system-inclusive scan can show Apple jobs in that same context. This option does not elevate privileges. Lifecycle controls require an explicit `allow_launchd` label-to-plist map under the ordinary agent user's `Library/LaunchAgents`, a matching GUI domain, safe ownership/permissions, a matching loaded path and unchanged content hash. Unloaded approved profiles remain observable. Apple/system jobs and boot-policy editing remain read-only. Actual launchctl output/context compatibility needs target testing.

The plist example is inert and contains no credentials. It is not an installer: review absolute paths and the ordinary user account first. Securely provision `PSC_AGENT_TOKEN` and the independent signing key through an appropriate local secret mechanism; never put secrets in the plist or registry notes. Until that is configured the agent refuses startup. `RunAtLoad` and `KeepAlive` are false; no launchctl load/bootstrap command was executed. Per-user LaunchAgents run only in the relevant user session.

Process control on Linux/macOS is limited to explicitly configured fixed absolute argv/cwd and previously verified agent-started identities. Unknown launches, PID reuse, changed executable/profile or stop timeouts inhibit control; automatic force-kill is unavailable. These invariants are mocked for both OS names; actual target execution remains unverified.

Automatic inactivity uses the same platform-independent controller policy on Linux, macOS and Windows, but it can stop only runtimes that already have explicit agent control permission. Linked applications require a profile for the parent and each component (up to eight); all signals must remain idle and every component must be running and controllable. Unknown or active signals, component revisions, missing permissions, stale hosts and external running dependents inhibit stopping. Unapproved/system launchd and Windows native services remain read-only. Socket permission failures are unknown activity, never idle.

Session 6 file and terminal adapters are mocked, not proof of native compatibility. Existing approved UTF-8 files only; hardlinks, unsafe paths and changed permissions are refused. Windows replacement uncertainty retains recovery evidence rather than blindly retrying. macOS copies metadata without copying file data. Live terminals require signed agent transport, ordinary-account checks and fixed local profiles; sessions and recordings are bounded. Content is not persisted unless recording is selected, and masking cannot guarantee removal of every secret. Follow [manual target checks](MANUAL-PLATFORM-CHECKS.md) to collect compatibility evidence first.
